### 实测得到的“不是 bug 但要知道”的事实

- `t = 16·exp(-1.2+1.5·N(0,1))`（sigma_data=16）→ 范围约 0–80；序列损失 `max_t=1`
  所以**只有 t<1（约 14.7% 的样本）**才产生序列损失，`train/per_epoch_seq_recovery`
  只在那些 batch 出现 → 小样本 smoke 跑里这列经常是空的/0。这是上游设计。
- lDDT 对**刚体变换天然不变**（我第一版审计误判成“不敏感”，因为平移不改变原子间距离）。
- `EMA.decay=0.999` 对短跑是灾难：572 步时 shadow 只走了 ~43% 的训练进程，
  而验证用的正是 shadow（`EMA.forward` 在 eval 模式转发到 shadow）。
  变体间对比仍自洽，但绝对 lDDT 被低估。想改就调 `model.ema.decay`（如 0.99）。
- `EMA.shadow` 的参数经 `detach_()` 后 `requires_grad=False`（实测）→ **不会**污染
  trainable 计数；只有 `parameters()` 总数会翻倍（即上表 #4）。
- `ReplacementNMFLinear` 把符号锁死（`weight_sign` 是 buffer，U/M/V 非负）→
  `sign(W_nmf)==sign(W_base)` 恒成立（实测 1.000），只能调 magnitudes。随机权重下
  rank-8 初始化的相对 Frobenius 误差约 0.51–0.60 → NMF 变体在 step 0 就与 baseline
  不等价，比较时要注意这个起跑线差异。
- `parameter_freezing_config` 缺省 = 不冻结（`freeze_by_default=False`）；
  完全冻结的模型 loss 没有 grad_fn，会在 `backward()` 崩 → 只能配零训练步使用。
- `is_original_unindexed_token` 的**层级两处定义不一致**：`conditioning_base.py:524` 存的是
  原子级（`apply_and_spread_token_wise` + 拼接扩展原子），`util_transforms.py:189` 注释写
  `[n_tokens]`，而 loss 里当 token 级用（`[tok_idx]` 索引）。只在 unindexed motif 训练时
  才有非零值（本 sweep 恒为全 False，`torch.any` 直接跳过分支），所以**没动它**——
  真要修得先确定作者意图。同类：`trainer/rfd3.py:336` 的 `# [D, L]` 注释也是错的
  （`mask_atom_lvl` 实际是 1D `[L]`）；`seq_token_lvl` 注释写 `[I,32]` 实际是 `[I]`。
- 周期性验证 `should_validate = current_epoch % validate_every_n_epochs == 0`；
  `recycle_schedule` 在构造时按 `(max_epochs, n_examples_per_epoch)` 生成，与
  `assemble_distributed_loader(n_examples_per_epoch=...)` 的 sampler 长度一致 → 无越界风险。
